机器人执行器控制与系统集成平台

技术主线：ROS 2 Jazzy 四关节左臂控制 + EtherCAT PDO。依据当前工作目录源码，2026-10-05；这是结构说明，没有新增实机验收。

打开逐模块详细说明与 Mermaid 流程图

1 · 任务到关节命令

应用客户端生成 joint_1/2/3/5 多点带时间轨迹，位置 rad
→
FollowJointTrajectoryGoal 接受、执行、取消、结果
→
轨迹控制器按时间生成 position 参考，检查轨迹容差
→
SystemInterface统一命令/反馈接口，连接两种后端

controller_manager 按 read → update → write 调度，默认目标 100 Hz / 10 ms。硬件后端二选一；该配置不代表硬实时已经验收。

2 · 模拟与物理后端

mock：接口和逻辑验证

SimSystem → SimCore整组命令校验、速度受限的模拟位置变化、故障注入

输出模拟 position / velocity 和健康字段。没有质量、摩擦和接触动力学，不能替代实机。

ethercat_left_arm：物理通信

LeftArmCore标定、限位、步长、速度、跟随误差、模式与状态检查
→
LeftArmBus / IgH四轴 PDO domain、WKC、链路和从站状态
⇄
p1 / p2 / p3 / p5 驱动器电机内部伺服与编码器反馈

rad → 编码器计数 → 0x607A；0x6064 原始位置 → rad。控制字 0x6040 请求状态，状态字 0x6041 反映实际状态。

3 · 反馈返回与可观察性

位置/速度状态接口返回控制器参与后续周期判断
→
joint_state_broadcasterjoint_states / dynamic_joint_states
→
URDF + TF + RViz把关节反馈转成连杆姿态；模型目前是示意

并行观察：diagnostics 检查健康和数据新鲜度；fault_snapshot 保存分层故障证据；bag_session 录制、归档、分析并在独立 domain 回放状态。

4 · 故障分支

异常越界、周期超时、缺反馈、总线或驱动故障
→
核心锁存任一轴失败阻断整组目标，不自动续跑
→
尝试整组失能物理插件发 controlword 0；read/write 返回 ERROR
→
框架与诊断错误处理、NaN 反馈、故障日志和快照

软件发送失能请求不等于确认机械停止。底层保护不等待 Python 诊断节点。

5 · 配套 Web 测试流程

页面 / SocketIO预检、观察、进度和报告
→
Flask 后台任务app.py 接收事件
→
ethercat_bridge本地/SSH 子进程、进程内锁、超时和输出解析
→
预检 / JE 观察程序结果推送并写日志和报告

Web/SSH 不进入 ROS 周期链。CAN/串口测试实现和 IMU 读取作为配套代码存在；当前 run_test / run_batch 已由服务器禁用历史动作。

6 · 阅读重点

为何要分成应用、控制器、核心和总线？

应用决定任务；控制器提供每周期参考；核心检查整组命令并换算设备单位；总线交换 PDO；驱动器负责实际电机伺服。各层可以独立验证和更换。

哪些内容不能当成默认运行行为？

STATE_MACHINE.md 描述 system_manager 与显式使能/恢复，但当前 control.launch.py 未启动该节点。文档中的 supervised_fault_stop、try_lock 等也与当前所读插件不一致。应核对部署版本，不能把所有快照混成同一条流程。

项目完成到什么程度？

已有标准控制链、模拟插件、物理插件源码、离线测试及历史模拟证据。新物理插件仍缺完整实机验收证据；RViz 显示、mock 通过、假总线通过都不能替代真实 PDO、标定、停机与闭环记录。

详细代码入口、转换公式、各模块解释、故障语义及一次完整动作示例见配套 Markdown。
