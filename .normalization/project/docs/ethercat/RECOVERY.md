# 掉站诊断与受控恢复

本文是恢复设计及后续实现约定，不是已实现自动恢复的说明。

## 现有行为

左臂插件检测不完整 WKC、链路/从站状态异常、驱动故障及模式丢失，锁存整组故障并尝试失能。
故障锁存跨 cleanup 保留；排除原因后需要重启。当前没有“从站回到 OP 后自动重使能并续跑”的功能。
旧脚本返回原位是运动动作，不是掉站恢复策略。

## 诊断顺序

1. 确认主站链路、拓扑与实际从站数量，保留失联发生前后证据。
2. 按位置核对 Vendor/Product、revision/serial；不能把更换设备当作原设备自动接纳。
3. 检查每站 AL 状态和错误、PDO 工作计数及数据是否持续更新。
4. 通信满足条件后检查 CiA402 statusword、error code 和 mode display。
5. 最后检查目标/反馈误差、单位换算和上层控制器状态，避免把电机故障归因为 ROS QoS。

当前左臂健康话题只有汇总接口；逐站 AL、WKC 原始值及首错快照属于待补能力。

## 规划中的恢复阶段

- **RUNNING**：整组控制正常。
- **FAULT_LATCHED**：取消当前任务、停止接受新运动，记录首个故障和后续变化。
- **WAIT_FOR_LINK**：只观察链路与设备，禁止持续自动 fault reset 或使能。
- **VERIFY_IDENTITY**：设备、拓扑或固件不匹配时停留在故障状态。
- **RECONFIGURE**：在非周期管理路径重建经过确认的 PDO/SDO/DC 配置；设置重试上限和超时。
- **VERIFY_FEEDBACK**：要求多周期 WKC、AL、状态字及模式一致，反馈新鲜且在合理范围内。
- **READY_FOR_ENABLE**：重建目标为当前实测位置，丢弃故障前轨迹，等待明确恢复操作。
- **ENABLING**：执行有反馈确认的 CiA402 使能；部分关节失败则整组退出。
- **RUNNING**：接收一条新任务；不自动续跑旧目标。

任一阶段失败都回到锁存状态，保留原因。上面的名称是设计名，代码目前没有该恢复状态机。

## 恢复记录最小字段

事件记录应包含 session_id、单调时间、设备位置/身份、首错与当前错误、AL、WKC/wc_state、
statusword/controlword、mode command/display、反馈年龄、重试次数、阶段、退出原因。
采集原始值，再添加解释，不能只保存“恢复成功”一行文本。

## 以后认定恢复完成的条件

链路恢复、从站 OP、设备使能、控制器重新激活、接收新任务分别记录时间。
需要覆盖掉线、错误设备替换、缺少从站、模式错误和恢复超时，证明不会自动续跑旧轨迹。
模拟场景用于验证状态机决策；真实断链、驱动看门狗和负载制动效果必须另留现场证据。

本轮不执行这些实验，不把上述条件标记为通过。
