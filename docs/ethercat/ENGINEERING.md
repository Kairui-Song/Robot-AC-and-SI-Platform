# EtherCAT 工程资料与交付规范

## 两条设备路线分别建档

JE 单电机实验与 EYOU 四关节左臂分别记录身份、PDO、固件、模式与周期配置。
型号展示名称不作为硬件识别依据；未知值留空。示例参数不自动提升为现场配置。

运行参数仍由 [left_arm_hardware.yaml](../../ros2_ws/src/linglong_control/config/left_arm_hardware.yaml) 及其加载器管理。
[commissioning.template.yaml](commissioning.template.yaml) 是资料记录模板，**不被驱动读取，也不能作为 hardware_config 传给 launch**。

## 一套完整设备档案

- 主站：主机、内核、IgH 版本、网卡/驱动、拓扑、周期与调度策略。
- 从站：位置、别名、Vendor/Product、revision、serial、固件及设备角色。
- ESI：原文件、厂商出处、版本、适用固件和 SHA-256；引用文件，不复制一段索引冒充完整 ESI。
- PDO：现场映射导出，SM/PDO/index/subindex/bit_length/direction，代码配置与现场差异。
- SDO：初始化写入对象、类型、单位、来源、目的和读回结果；配置阶段与周期阶段分开。
- 标定：位置/速度/转矩单位、减速比、方向、零位、限位及测量记录。原始转矩未经换算不标 Nm。
- 同步：DC 是否启用、AssignActivate、Sync0 周期/相位、参数依据和同步测量。
- 停机：正常停用、故障、总线中断、进程退出、看门狗到期和制动器响应，分别记录。

## 代码归属与变更范围

ROS 参数、生命周期、接口导出放在 SystemInterface；算法无关的整组校验放在控制核心；
ecrt 访问与过程映像放在总线适配层。Web 的进程、报告和页面逻辑不放进周期函数。
单电机实验可以继续存在，但不直接复制其设备身份、单位、DC 或使能时序覆盖左臂配置。

当前已有布局不迁移。准备移动文件时，先列出 Python import、CMake、launch、安装脚本、
Web 路径和现场部署依赖，再改动；`_1/_2/_3` 副本先确认用途后归档。

## 周期与日志约定

周期函数避免 shell/SSH、阻塞 SDO、磁盘日志和无界等待；初始化与恢复管理放在非周期路径。
这是一项后续审查要求，不代表仓库所有 JE 实验变体已经满足；例如周期中的 printf 仍需逐项评估。
指标必须标明时钟、采样率、样本数、负载、阈值来源和执行环境。

每次记录使用独立目录，保存配置副本、源码/构建标识、原始数据和结论。
不能覆盖失败日志，只保留最后一次成功；配置改动后的结果不能归给旧配置。

## 完成程度的提升条件

1. **源码实现**：明确支持的设备、接口、失败行为及未支持项。
2. **离线验证**：保存对应控制核心/参数校验的执行结果；不推导 ROS 或硬件结论。
3. **ROS 集成**：真实加载插件与控制器，记录 Action、取消、生命周期和故障传播。
4. **硬件通信**：保存设备身份、PDO/WKC、模式及真实反馈，不以 mock 替代。
5. **实机闭环**：在已确认的标定与停机条件下记录目标、反馈和状态。
6. **性能与恢复**：约定条件/门槛后测量 jitter、同步、故障和受控恢复。

本次只整理第 1 层的工程表达及资料结构，不提高任何已有模块的验证等级。

## 后续实施顺序

先补设备档案和 ESI/PDO 来源，再统一逐站诊断；随后复核 DC 时基、同步参数及周期指标。
在这些基础上实现受控恢复管理；CSV/CST 作为独立扩展，不与 CSP 或模式探测混称。
新 ROS 运行时验证和实机验证继续按 [VERIFICATION.md](../../ros2_ws/VERIFICATION.md) 分开推进。
